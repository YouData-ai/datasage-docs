The **Dashboard** in the platform provides a centralized view of the overall health, usage, and activity of your data ecosystem. It is divided into three main tabs:
- **Analytics**
- **Monitoring**
- **Activity**

![Dashboard UI](/images/dashboard.png)

---
### 1. Analytics 

This tab provides a high-level summary of the platform usage and performance:

#### View Summary Metrics
You will see four key metric cards at the top:
- **Data Sources**: Total number of integrated data sources. Example: `66`
- **Pipeline Uptime**: Current uptime of the data pipeline. Example: `100.0%`
- **Active Alerts**: Number of ongoing system alerts with severity tags (e.g., Warning, Critical).
- **Data Usage**: Count of total operations or accesses performed on data. Example: `142`

#### Analytics Panels
This section gives graphical insights:
- **Data Volume by Source Row Count**:A bar chart showing how many rows of data exist per source (e.g., File, MySQL, PostgreSQL, Snowflake).
- **Data Access Distribution** : A donut chart showing how different data sources are being accessed or queried by users.
- **Usage Trends (6 Months)**: Line chart showing platform usage over time.

### 2. Monitoring 

This tab monitors pipeline health and data processing performance in real-time.

### Key Components Monitored

| Component              | Description                                                                 |
|------------------------|-----------------------------------------------------------------------------|
| **Raw Data Ingest**    | Indicates the status of data coming directly from the source.               |
| **Silver Layer (ETL)** | Reflects Extract-Transform-Load operations for cleaned intermediate storage.|
| **Gold Layer (Migration)** | Shows migration status of refined data for analytics.                |
| **Schematization**     | Ensures the schema mapping and formatting of data.                          |
| **Transformation**     | Reflects the final transformation applied to data before usage.             |

Each component shows:
- **Status**: (Healthy, Unknown, Alert)
- **Health Bar**: Indicates processing completeness in percentage.


###  Pipeline Latency Chart
- Displays the processing time for each pipeline stage.
- Helps identify performance bottlenecks.
- Example: If `Raw Data Ingest` takes **389,600 ms** and `Transformation` only **700 ms**, it indicates potential delay upstream.

![Dashboard UI](/images/monitord.png)

### Active Alerts
- Lists any critical or warning alerts based on component status.
- Assists in prompt debugging and system reliability.  

---

### 3. Activity 

This section tracks recent user activities and system events in real time.

**Key Activity Logs**

| Activity Example                     | Description                                                                 |
|--------------------------------------|-----------------------------------------------------------------------------|
| **Accessed Dashboard**              | User viewed a specific dashboard area (e.g., Overview, Settings).           |
| **Data Transformation Completed**   | Indicates a successful transformation job with data size and duration.      |

###  How It Helps
- Tracks when users interacted with the dashboard and modules.
- Helps admins audit data operations.
- Useful for debugging and understanding user behavior.

![Dashboard UI](/images/activityd.png)

---

###  Benefits

- Real-time health check of the pipeline flow.
- Performance diagnostics via latency analysis.
- Transparent activity trail for operational oversight.
