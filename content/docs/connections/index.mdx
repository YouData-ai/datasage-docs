The Connection module in DataSage is the foundational layer that enables the platform to connect external data sources to the DataSage environment. It acts as a bridge between the platform and external data sources. . It allows users to configure and manage secure connections to databases (e.g., MySQL, PostgreSQL), APIs (e.g., REST), cloud platforms (e.g., Snowflake, AWS S3), and other file-based or service-based sources. Without configuring a connection, no ingestion, transformation, monitoring, or querying can be performed.

### How the Connection Works

#### 1. **Create a New Connection**
- Navigate to the **Connection** module from the sidebar.
- Click on the **“+ New Source”** button.
- Select the **source type** (e.g., PostgreSQL, S3, Snowflake, REST API, etc.).
- Fill in the required configuration details:
  - **Connection Name**
  - **Host**
  - **Port Number**
  - **Username / Password**
  - **Database Name / Bucket Name (if applicable)**
- Click **Save** to store the connection.

![Connections UI](/images/connect-source.png)

### Test & Verify Connection (Online/Offline)
- Each connection can be tested after creation or during edit using **“Test”** button.
   - If the connection is successful, status shows **Online**.
   - If failed, status shows **Offline** with error message.
   - This helps validate:
     - Correct credentials
     - Network accessibility
     - Source availability

### Manage Connections

#### Edit a Connection
- Click the **Edit (✏️)** icon on the connection.
- Update credentials or other parameters.
- Click **Update** to verify.
- Click **Save** to update the connection.

![Connections UI](/images/connect-source.png)

#### Delete a Connection
- Click on the **Delete (🗑️)** icon.
- A confirmation popup appears.
- Confirm deletion to remove the connection permanently.
- *Deleting a connection also affects all dependent pipelines or ingestions.*


#### View Logs
1. Go to **Monitor > Logs** section.
2. Filter logs by **Connection Type** or name.
3. View:
   -  **Success logs** – when a connection is created/tested successfully.
   -  **Failure logs** – if connection test fails or times out.
4. Click the log entry to view **error messages success/failed**, such as:
   - Connection failed.
   - Connection success.


###  **Use in Ingestion or Pipeline**
- Once verified, the connection becomes selectable in:
  - **Ingestion module** – to ingest datasets
  - **Pipeline module** – for transformation and flow configuration
  - **SageMind / Playground** – for data queries and visualizations

You are now ready to ingest and query data from your MSSQL source in DataSage.Ai!

---
**Important Note**

####  Current Destination Setup: Amazon S3

Currently, the platform only supports **Amazon S3** as a destination. The S3 destination must be **pre-configured** before it can be used to store or send data.

####  Future Support: Multiple Destination Connectivity

In the future, the platform will support **dynamic connection to multiple destinations**, similar to how multiple sources are currently supported.
