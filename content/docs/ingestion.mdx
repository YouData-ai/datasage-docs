## Set Up a Ingestion

The platform supports a wide variety of connectors, including SQL databases, Files, cloud storage, APIs, and more.

![Ingestions UI](/images/ingestion.png)

### View Available Sources
- All connected sources (e.g., MySQL, MongoDB, REST API, etc.) are listed here.
- Each source is represented as a collapsible item.

### 1. Connection Setup
Before starting the ingestion, you must first create a connection. This connection will allow the platform to access the data from your selected source.

### 2. Source Selection

Once the connection is established:
- Navigate to the **Ingestion** section.
- Choose from the list of **existing sources** that have already been connected.

![Ingestions UI](/images/Existing.png)

### 3. Destination Selection

After selecting the source:
- Choose the **destination** where the ingested data will be stored.
- The destination (such as an S3 bucket, database, etc.) should already be added/configured in the system.

![Ingestions UI](/images/Destination.png)

### 4. Choose Database and Table (Source Specific Behavior)

Depending on the type of source selected:
- For sources like **Microsoft SQL Server**, **MySQL**, **PostgreSQL**, etc., you will be required to select both a **database** and a specific **table**.
![Ingestions UI](/images/stream.png)
- For **Snowflake** you may only need to select the **database**, and not a specific table.


![Ingestions UI](/images/indatabse.png)

- For **RestApi** you may only need to select the **Json**, and not a specific table.
![Ingestions UI](/images/restapi.png)

### 5. Configuration
After selecting both source and destination, proceed to **configure the connection**. This configuration includes the following settings:

#### a. Schedule Type
- **Selected Option**: `Scheduled`
- **Purpose**: Defines when the sync should be triggered.
- **Note**: You can choose between manual or scheduled syncs. In this case, it is set to run automatically on a scheduled basis.

#### b. Replication Frequency
- **Selected Option**: `Every 6 Hour`
- **Purpose**: Specifies how frequently data should be replicated (synced) from the source to the destination.
- **Example**: With this setting, the data will automatically sync every 6 hours.

#### c. Sync Mode
- **Selected Option**: `Incremental | Append + Deduped`
- **Purpose**: Controls how the new records are handled.
  - **Incremental**: Only new or changed data is synced.
  - **Append + Deduped**: New records are appended while ensuring duplicates are removed.
- **Benefit**: This helps in maintaining data uniqueness and reducing load.

#### d. Final Step: Finish and Sync
- Click the **Finish & Sync** button to apply the configuration and begin the sync process.

#### Summary
This setup ensures that:
- The sync runs every 6 hours.
- Only new or updated data is transferred.
- Duplicates are avoided using deduplication.
- Data flows from PostgreSQL to AWS S3 reliably and automatically.

### Connection Overview

The **Connection Overview** provides a complete summary and real-time visibility of the data ingestion process. It includes two main sections:

#### 1. Status Overview

The **Status** tab displays key metrics and metadata after an ingestion is completed. It helps you verify if the operation was successful and review data flow details.

**Example Information Shown:**
- **Execution Time**: Total time taken to complete ingestion 
- **Total Records**: Number of records pulled from the source 
- **Total Tables**: Number of tables ingested (if applicable)
- **Tables with Incremental Mode**: Count of tables using incremental sync
- **Source Type**: Type of source (e.g., `REST API`, `MSSQL`, etc.)
- **Source Name**: The name of the connected source
- **Created At / Updated At**: Timestamps of ingestion and updates
- **Sync Mode**: Whether incremental mode was enabled
- **Records Skipped**: Records ignored during ingestion
- **Error Tables**: If any, error tables will be listed here
- **Scheduler**:A manual or on-demand run was performed as no scheduler was enabled at the time of this ingestion.
      * **Status:** Disabled/Enabled.

![Ingestions UI](/images/status.png)

#### 2. Logs Overview

The **Logs** tab tracks each step of the ingestion process with timestamped events. This is useful for debugging and verifying data pipeline stages.
Each log line contains:
- **Event Name**
- **Timestamp**
- **Details**: connector ID, row and column counts, missing values, destination path, status, etc.

 **Typical Logged Events Include**:
- `Started`: When the ingestion job starts
- `API_REQUEST_STARTED`: API request is initialized
- `API_DATA_RETRIEVED`: Data is fetched from the source
- `DATA_QUALITY_CHECK`: Checks for missing or duplicate values
- `DELTA_CONVERSION_STARTED`: Delta logic or incremental conversion begins
- `S3_UPLOAD_STARTED`: Upload begins to destination like S3
- `Completed`: Indicates successful ingestion
- `EDA_STATS_API_CALLING / CALLED`: Additional steps for exploratory data analysis
- `CLEAR_LAYER_API_CALLING / CALLED`: Final cleanup or layer processing
