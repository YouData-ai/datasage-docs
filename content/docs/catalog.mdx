## Catalog Overview

The **Catalog** module in the DataSage platform is a metadata management system that enables structured organization, discovery, and enrichment of datasets across various connected sources. Rather than simply being a UI display, it performs a series of backend operations that involve metadata extraction, profiling, tagging, and transformation pipelines to prepare the data for exploration and downstream use.

![Catalog UI](/images/catalog.png)
---

### ️ How Catalog Works

#### 1.  **Data Source Connection**
- Catalog depends on successful **Ingestion established** via the "Ingestion" module.
- Once a connection (e.g., PostgreSQL, MySQL, Snowflake, REST API, S3, etc.) is created, it enables access to source schemas.

#### 2.  **Ingestion and Schema Crawling**
- Upon ingestion or metadata fetch trigger:
  - The Catalog **crawls the schema** of each connected source.
  - Extracts metadata like table names, column names, types, constraints, row counts, and structure.
  - Stores this metadata in a central metadata store (e.g., internal metadata DB or indexing service).

![Catalog UI](/images/schema.png)

#### 3.  **Metadata Profiling and Quality Scanning**
- Runs **data profiling jobs** for each table:
  - Detects column data types.
  - Identifies null/missing values.
  - Scans for outliers, duplicates, and data inconsistencies.
- Generates quality scores (e.g., 100% quality) based on rules.

#### 4. **Data Standardization and Transformation**
- Applies standard transformations to bring consistency:
  - Column name formatting (lowercasing, removing spaces, special characters).
  - Infers and assigns data types uniformly (String, Integer, DateTime, Float, etc.).
  - Tags column-level metadata using ontologies and NLP models.

#### 5. ️ **Tag and Ontology Mapping**
- Auto-generates **semantic tags** for columns and tables using:
  - Predefined taxonomies (like “E-Commerce”, “User Details”, etc.).
  - AI-based inference (field names, values, relationships).
- Tags improve contextual understanding and searchability.

#### 6.  **Metadata Indexing**
- Catalog metadata is **indexed** for fast retrieval using:
  - ElasticSearch or internal vector store.
  - Supports full-text and semantic search over tables, columns, and tags.

#### 7. **Processing and Sync Scheduling**
- Catalog can be updated via:
  - Manual ingestion triggers.
  - Periodic refresh schedules (hourly, daily, weekly).
  - Change Data Capture (CDC) events (in future versions).

---

### Benefits of Catalog Architecture

- Centralizes metadata across all sources.
- Enforces consistency via transformations.
- Supports intelligent discovery using tags and summaries.
- Makes data governance and compliance easier.
- Acts as a **single source of truth** for all datasets.

---
#### Features:
- Displays a list of all available databases
- Allows easy search and navigation of tables/entities
- Each database shows a count of tables (entities) under it
